# Настройки профиля: email и SFI

## Причина неисправности уровня

В `bindEvents` обработчик `profile-level` выполнялся только при `!cloudAccount()`.
Дополнительно `renderProgressUX` отключал `#profile-level` для облачного аккаунта.
В модуле прогресса не было операции записи настроек. Поэтому аккаунт читал уровень
из Supabase, но изменить его через кабинет было невозможно. Значение A в
`defaultState` могло отображаться до загрузки облачного состояния.

Исправление использует существующий контракт миграций 001–009:
`sl_apply_event`, `type: settings_update`, `data: {level: 'A'|'B'|'C'|'D'}`.
Перед записью читается актуальная ревизия. Запись использует тот же Web Lock,
что очередь учебных событий. При 40001 выполняется один повтор; UUID и тело
события сохраняются. При потере ответа повтор того же выбора использует прежний
UUID в текущей вкладке. Успех показывается только после валидного ответа сервера.
Изменения других устройств перечитываются при возвращении фокуса на страницу.
Явное сохранение уровня работает и на localhost без включения фоновой записи
учебных событий. Учебные данные и локальные хранилища этой операцией не меняются.

## Изменённые файлы

- `app.js`: единый блок настроек, редактор email, сохранение уровня, обновление значка, сообщения на четырёх языках и обновление email при событиях Auth.
- `supabase-auth.js`: официальный `auth.updateUser({email}, {emailRedirectTo})`, проверка текущего пользователя через `getUser`, обновление Auth при возврате фокуса.
- `supabase-progress.js`: сохранение уровня через существующий RPC, сериализация и обновление облачного снимка.
- `style.css`: компактная адаптивная форма email и место под сообщения.
- `sw.js`: версия кеша для обновлённых ресурсов при следующей публикации.
- `tests/supabase-preparation.cjs`: проверки Auth и записи уровня.
- `tests/word-progress-dom.cjs`: источник email из Auth и поведение интерфейса настроек.
- `docs/PROFILE_SETTINGS.md`: этот отчёт и ручная проверка.

SQL-миграции не изменялись и не применялись. Деплой не выполнялся.
localStorage и IndexedDB не очищались. Секретные ключи и пароли не добавлялись.

## Ручная проверка

1. Открыть localhost (`http://127.0.0.1:8765/`) и войти в тестовый аккаунт.
   Зафиксировать XP, изученные слова, избранное, повторения, уроки и время занятий.
2. В кабинете выбрать SFI B, C, D по очереди. После каждого ответа проверить значок.
   В DevTools → Network проверить успешные `sl_get_progress` и `sl_apply_event`:
   тип `settings_update`, только `data.level`, успешный ответ с выбранным уровнем.
3. Перезагрузить страницу; выйти и снова войти; войти на другом устройстве.
   Уровень должен остаться D, прогресс — прежним. Учёт времени при активной учёбе
   может закономерно увеличиваться. Изменить уровень на втором устройстве и
   вернуться к первой вкладке: значение должно обновиться при фокусе.
4. Отключить сеть и попытаться изменить уровень. Не должно быть сообщения об
   успехе; выбор возвращается к последнему серверному значению. Включить сеть и
   повторить. Проверить отсутствие неожиданных ошибок в Console и RPC.
5. В настройках нажать «Изменить email». Проверить отмену и некорректный адрес.
   Затем указать доступный тестовый адрес и сохранить. До подтверждения текущим
   должен оставаться старый email. Сообщение: «Проверьте почту для подтверждения
   нового адреса». Проверить ошибки сети и занятый адрес отдельного тестового аккаунта.
6. При Secure email change подтвердить письма **на обоих адресах**. Первый переход
   может ещё не завершить смену. Завершить все подтверждения, вернуться в кабинет.
   Проверить новый email, сохранённую авторизацию, тот же аккаунт, уровень и прогресс.
   Повторить с возвратом в исходную вкладку и после перезагрузки.
7. Проверить истёкшую ссылку и истёкшую сессию тестового аккаунта: понятная ошибка,
   отсутствие ложного успеха. Не публиковать токены из URL, логов и Network.
8. На ширинах 360, 390, 768 и 1280 px проверить перенос длинного email, кнопки,
   клавиатурную навигацию, отсутствие горизонтальной прокрутки и потери фокуса
   при обновлении Auth/прогресса. Проверить Console и Network на desktop/mobile.

## Supabase Dashboard

Проверить Authentication → URL Configuration:

- Site URL: `https://voziianofficial.github.io/Svenska_Latt/` для production.
- Redirect URLs: `https://voziianofficial.github.io/Svenska_Latt/` и
  `https://voziianofficial.github.io/Svenska_Latt/index.html`, если используется такой вход.
- Для разработки добавить точные используемые адреса с портом:
  `http://localhost:8765/`, `http://127.0.0.1:8765/` и варианты `index.html`,
  если приложение открывается с этим путём. Другие порты добавляются отдельно.

Клиент отправляет redirect как `location.origin + location.pathname`, без токенов
и hash маршрутизатора. Существующий обработчик callback очищает токены/код из URL
и восстанавливает сессию. Путь `/Svenska_Latt/` на GitHub Pages сохраняется.

В Authentication → Email проверить Secure email change, шаблон Change Email
(штатный `ConfirmationURL`), SMTP/доставку и ограничения отправки. При включённой
Secure email change ожидаются подтверждения старого и нового адреса. Не отключать
защиту ради локального теста. Проверить Auth logs при проблемах доставки.
Клиент не может прочитать или изменить эти настройки Dashboard.

Документация: [Supabase updateUser](https://supabase.com/docs/reference/javascript/auth-updateuser),
[Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls).
