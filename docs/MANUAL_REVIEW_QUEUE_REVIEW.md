# Персональная очередь повторения: локальные изменения для проверки

Дата: 18 октября 2026. В настоящий Supabase запросы не отправлялись, SQL не применялся, деплой не выполнялся.

## Причина прежнего поведения

`action('mark-review')` выполнял `navigate('word-review', id)`, не сохраняя намерение пользователя. Раздел `renderReviews()` вызывал прежний список на основе `dueIds()` / `state.reviews`: это наступившие сроки SRS, а не ручная очередь.

Миграции 007 недостаточно. `mark_review` сохраняет отрицательный результат, вызывает `sl_private.review(..., false, ...)` и учитывает учебную активность. `review_grade` сохраняет оценку ответа. Ни одно событие не выражает членство слова в персональной очереди. Существующие события не переинтерпретируются, автоматические сроки не импортируются в ручной список.

## Новая серверная структура

Полный SQL для предварительной проверки: [202610180009_manual_review_queue.sql](../supabase/migrations/202610180009_manual_review_queue.sql).

Миграция 009 требует 007, совместима с 008 и не зависит от таблиц трекера времени. Файлы 001–008 не изменены. До применения 009 новая функция честно сообщает о недоступности сохранения.

- `sl_review_queue`: одна запись на `(user_id, word_id)`, признак активности, UUID версии и порядок изменения. Неактивные записи сохраняются как защита от устаревших запросов.
- `sl_review_receipts`: постоянные квитанции `(user_id, request_id)` с исходным запросом и результатом проверки конфликта. Повтор UUID с другим телом отвергается.
- `sl_review_list()`: согласованный снимок очереди с собственной монотонной ревизией; сроки SRS в него не входят.
- `sl_review_change(...)`: действия `add`, `remove`, `remember`, `again`. Получает аккаунт только через проверенный `auth.uid()` и общий `lock_account()`.
- На обеих таблицах RLS, SELECT только своих строк. Прямые INSERT/UPDATE/DELETE от клиента запрещены. RPC доступны только authenticated, имеют пустой `search_path`, проверяют слово по серверному каталогу.

Добавление активного слова — безвредная операция без дубликата. Удаление, повторное добавление и оценка требуют актуальной UUID-версии. Завершённая старая попытка не удалит слово, которое пользователь добавил снова. Разные устройства, одновременно оценивающие одну версию, сохранят ровно одну оценку.

Добавление и ручное удаление не меняют прогресс, SRS, XP, известность, избранное, активность и историю. Оценка вызывает существующий `sl_apply_event(... review_grade ...)` внутри той же транзакции. `remember` деактивирует запись; `again` оставляет её активной и обновляет версию попытки. Ошибка сохранения очереди откатывает оценку SRS и событие целиком. Оценка не меняет «Знаю» и не приносит XP, как определено в 007.

## Клиент и UX

`manual-reviews.js` работает независимо от старой очереди учебных событий и её локального переключателя. Использует существующий транспорт `SVRpc`: проверка пользователя и контекста авторизации, привязка RPC к захваченному JWT, без сохранения токенов в новом модуле.

Кнопки в словаре и на странице слова добавляют слово, показывают «Сохраняем…», затем «✓ В повторении» после подтверждения сервера. Упражнение автоматически не открывается. Повторные нажатия блокируются. Ручной список доступен через существующий маршрут «Повторение» и отдельную кнопку со счётчиком в кабинете; показывает слово, перевод, доступное фото, запуск упражнения и удаление.

Упражнение сначала скрывает перевод, требует раскрытия ответа и только затем разрешает оценку. После подтверждённого «Вспомнила» слово отсутствует в активном списке. После «Не вспомнила» остаётся для следующей попытки. Прямой URL удалённого слова не запускает устаревшую попытку.

Оповещения очереди обновляют кнопки и строки без повторного построения словаря, сброса фильтров, поиска и прокрутки. При удалении списка сохраняется высота страницы; оставшиеся DOM-строки сохраняются. Для словаря заданы постоянные ширины кнопок; на узких экранах действия переносятся, а кнопки строки повторения занимают отдельный ряд.

Синхронизация устройств: чтение при входе, фокусе окна, возврате на вкладку и каждые 15 секунд в видимой вкладке. Собственная ревизия снимка предотвращает откат интерфейса из-за переставленных сетевых ответов. При смене аккаунта память очищается, поздние ответы прежнего аккаунта игнорируются.

## Офлайн без изменения браузерного хранилища

Новый модуль не читает и не изменяет localStorage или IndexedDB; их существующие форматы и данные сохранены. Изменение, начатое заведомо офлайн, не принимается как сохранённое: пользователь получает короткое сообщение и повторяет действие после подключения. Слово не исчезает из очереди из-за такой попытки.

Если запрос отправлен, но подтверждение потеряно, его исходный UUID и версия остаются в памяти открытой страницы. Переподключение повторяет тот же запрос: квитанция предотвращает повторную оценку SRS. Пока результат неизвестен, повторное действие для того же слова блокируется.

После закрытия/обновления страницы неподтверждённое намерение не восстанавливается из браузерного хранилища. Восстанавливается фактическая серверная очередь: подтверждённые сервером изменения остаются; недошедшее до сервера действие нужно повторить. Это намеренное ограничение при запрете изменений localStorage/IndexedDB. Офлайн-загрузка ранее не загруженной персональной очереди тоже не имитируется.
