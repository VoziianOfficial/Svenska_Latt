# Проверка интерфейса повторений и учебного времени

## Что исправлено

Основная подтверждённая причина отсутствия времени: `study-time.js` запускался только на localhost при наличии `sv-study-time-dev-v1=enabled`. На обычном домене он не создавал контекст пользователя и не вызывал ни один study RPC. Этот барьер удалён. Миграция 011 меняет значение по умолчанию на `enabled: true` для аккаунтов без сохранённой настройки. Ручное отключение сохраняется. Для включения нового поведения на сервере нужно применить `202610180011_study_time_default.sql` после 008; в этой задаче production не менялся.

Дополнительно чтение `sl_get_progress` могло ждать бесконечно. Теперь через 8 секунд оно переходит в состояние ошибки с повторной попыткой; поздний ответ не заменяет прогресс. Study RPC уже имели ограничение 8 секунд. Ошибки записи времени теперь также отражаются в компактной строке состояния.

Кнопка на странице слова восстановлена по реализации `HEAD` (`79cb5f0`, `renderWord` и `word-panel-actions`): `btn secondary`, значок 🔁, название «Повторить», существующие стили и анимации. В словаре используется компактный вариант с фиксированной шириной. Текст и геометрия больше не меняются при ожидании и подтверждении; добавленное слово получает мягкий зелёный фон и `aria-pressed`. Нажатие по-прежнему вызывает существующую персональную очередь. `manual-reviews.js`, SQL очереди и её обработка добавления/удаления не изменены в этой задаче.

Вместо отдельного календаря и графика время встроено в существующий `heatmap()` / `.activity-calendar`. Отметки `state.activity`, их цвета и навигация по месяцам сохранены. Статистика времени загружается через `sl_study_status` для выбранного месяца; суммарные значения возвращаются сервером. Неуспешная загрузка не выдаётся за день без времени.

Часовой пояс берётся из `Intl.DateTimeFormat().resolvedOptions().timeZone`. При отличии от настроек сервера текущая аренда закрывается, её сохранённые интервалы отправляются, затем вызывается `sl_study_settings` с прежним согласием и текущим `generation`. Исторические дни не пересчитываются. Разделение новых интервалов по полуночи и DST остаётся в существующей миграции 008.

## Обязательная ручная проверка перед релизом

1. Открыть локальный проект с этими файлами и войти в существующий Supabase-аккаунт. Не очищать хранилища и не запускать SQL. В DevTools → Network включить Preserve log, Console оставить открытой. Убедиться, что `study-time.js?v=2` загружен с HTTP 200, ошибок JavaScript нет.
2. После применения 010 проверить новый аккаунт: учёт включён без посещения настроек, время записывается во время занятий. В кабинете проверить один календарь «Активность по месяцам», прежние отметки и цвета, четыре карточки времени с датами текущих периодов и один переключатель. Нули допустимы, если учёт ранее не включался. При ошибке должна появиться короткая строка с повторной попыткой, а не бесконечная загрузка.
3. При выключенном переключателе открыть карточки на 30 секунд. В Network не должно быть `sl_study_open` / `sl_study_commit`. Включить учёт вручную, затем вернуться в карточки и взаимодействовать с ними 40–60 секунд. Должны пройти `sl_study_settings`, `sl_study_open` и примерно каждые 20 секунд `sl_study_commit` без ошибок; ответы PostgREST должны содержать корректные результаты, не только статус HTTP.
4. Вернуться в кабинет. `sl_study_status` должен вернуть увеличившиеся `totals` и `days` для текущей даты. В Supabase Table Editor, только чтением, проверить свои строки `sl_study_days` и `sl_study_periods`: `milliseconds` и интервалы должны увеличиться. Не менять и не удалять строки.
5. Обновить страницу. Время должно снова загрузиться с сервера и не обнулиться. Навести на сегодня: дата и «Обучение: …». На дне без записей — «Нет записанного времени». Переключить месяц и проверить `p_month` запроса `sl_study_status` и подсказки за выбранный месяц.
6. Оставить карточки без взаимодействия более 90 секунд: запись должна остановиться. Для открытого урока/книги порог чтения — 5 минут. Затем выполнить действие и проверить возобновление. Меню выбора упражнений само по себе не считается занятием.
7. Скрыть вкладку на 40 секунд, затем вернуться. Скрытое время не должно добавиться. Проверить потерю фокуса и две вкладки: параллельного двойного начисления быть не должно. Выключить учёт и проверить прекращение новых записей.
8. Сравнить результат `Intl.DateTimeFormat().resolvedOptions().timeZone` в Console с `timezone` ответа `sl_study_status`. В браузере с поддержкой эмуляции часового пояса изменить зону и вернуть фокус приложению. В течение очередного обновления (примерно 20 секунд) настройки должны синхронизироваться без ручного выбора и без включения выключенного согласия. Исторические строки должны остаться прежними. DST обрабатывается серверной зоной; визуальная эмуляция часов сама по себе не проверяет серверный переход времени.
9. В словаре нажать «🔁 Повторить». До подтверждения и после него размеры кнопки, карточки и положение страницы должны быть прежними; после подтверждения меняется фон. Упражнение не открывается. Слово появляется в персональной очереди; после перезагрузки остаётся там. Удаление из очереди работает по-прежнему.
10. Повторить проверку на Mac и телефоне: нажатие на день открывает небольшую подсказку внутри экрана, нажатие вне её закрывает; на Mac работают наведение и клавиатура. Проверить узкий экран, отсутствие горизонтального скролла, скачков и перекрытия экрана. При кратком отключении сети интерфейс остаётся доступным; после восстановления обновляются реальные значения.

Релизная проверка не завершена до выполнения пунктов с реальным аккаунтом и визуальной проверки на устройствах.
