## Service Worker и сервер

Фотографии загружаются по запросу; отдельный FIFO-кэш хранит максимум 150
просмотренных фотографий. Записи и вытеснение сериализованы, лимит проверен
при 205 одновременных загрузках. Фотографий в предзагрузке нет. Просмотренные
иконки слов и аватары сохраняют офлайн-доступность. API и посторонние ресурсы
не попадают в кэш оболочки.

Сборка вычисляет версию по содержимому всех файлов деплоя; при изменении любого
файла получается новый sw.js и новые имена кэшей. Активация удаляет старые
кэши только с префиксом приложения. Установка обходит HTTP-кэш, запросы
оболочки и впервые просматриваемых фото требуют HTTP-перепроверки.
Версионированные CSS/JS URL находят канонические офлайн-копии.

server.py отдаёт нужные CSS/JS, страницы, изображения, JSON и манифест с MIME.
URL декодируется один раз и нормализуется; проверяются разрешённые публичные
пути, `..`, обратные слеши, NUL, выход после resolve и символические ссылки.
index.html и sw.js имеют Cache-Control: no-cache. Авторизация и SQLite сохранены.

одного и того же состояния даёт одинаковые SHA-256 и версию кэша.
Для локального режима с прежним кабинетом: `python3 deploy/server.py`.
На статическом хостинге остаётся существующий гостевой режим; Python API
требует Python-хостинга. На выбранном хостинге перед публикацией настроить
